## Ответы на вопросы

**1. Чем отличается CI от CD?**
CI (Continuous Integration) — автоматическая проверка кода при каждом push: сборка, линтер, тесты. CD (Continuous Delivery/Deployment) — автоматическая доставка кода в продакшен. В проекте: задача `ci` — это CI, задача `deploy` — это CD.

**2. Что произойдёт, если тесты завершатся ошибкой на этапе CI?**
Пайплайн остановится на шаге `Run tests`. Последующие шаги (`Build`, `Upload artifact`) не выполнятся. Задача `deploy` не запустится, потому что зависит от `ci` через `needs: ci`. Развёртывание не произойдёт — сайт останется в предыдущей версии.

**3. Для чего используется директива `needs: ci` в задаче развёртывания?**
`needs: ci` создаёт зависимость: `deploy` запустится только после успешного `ci`. Если `ci` упал — `deploy` не запускается вообще. Это защищает продакшен от неработоспособного кода.

**4. Что такое артефакт и для чего он передаётся между задачами?**
Артефакт — это файлы, сохранённые после шага пайплайна. В проекте `ci` сохраняет папку `dist/` как артефакт `site-build`, а `deploy` его скачивает. Нужно потому, что `ci` и `deploy` выполняются на разных виртуальных машинах и не имеют общего файлового пространства.

**5. Почему развёртывание не запускается на Pull Request?**
В задаче `deploy` есть условие `if: github.ref == 'refs/heads/main'`. При Pull Request ветка — не `main`, поэтому условие ложно и `deploy` пропускается. Это защищает продакшен: в него попадает только код, влитый в `main`.
